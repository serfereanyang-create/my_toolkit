# 科研论文辅助工作台极简专业 UI 重设计

日期：2026-07-18  
状态：已实现  
范围：Electron 桌面端界面结构、视觉系统与交互层；账户、SQLite 和论文业务逻辑保持不变

## 1. 背景

当前界面虽然提供冰川冷色、暖纸感和深色主题，但主题差异主要停留在基础颜色变量上，三套主题共用相同的表面层级、阴影、间距和组件结构，导致亮色主题观感接近。主页面固定使用左右各 280px 的三栏布局，在 1100–1360px 桌面窗口中压缩了编辑区域；账户资料、修改密码和退出操作集中在狭长气泡内；右侧质量检查始终占位，使论文阅读和编辑不是绝对视觉主体。

当前 `src/App.tsx` 同时承载账户、主题、论文库、编辑器、证据、质量检查和导入导出 UI，文件过大，不利于持续调整布局与视觉细节。

## 2. 已确认方向

- 主视觉：**极简冷色专业风**
- 主结构：**双栏 + 右侧按需抽屉**
- 主题策略：保留三套，但视觉差异必须明显
- 实施位置：直接修改项目本体，不制作独立外部原型
- 保留现有账户、SQLite、会话、论文隔离、导入导出和自动保存业务

## 3. 目标

1. 让论文编辑区成为主视觉和主要空间使用者。
2. 消除固定三栏在最小桌面窗口中的拥挤。
3. 让三套主题在背景、表面、边框、阴影和状态反馈上明显不同。
4. 提高中文界面的字号一致性、信息层级和可编辑性提示。
5. 将账户与质量检查从窄气泡/固定侧栏迁移为宽抽屉。
6. 将大型 `App.tsx` 拆为职责明确、可独立维护的 UI 组件。
7. 保持所有已完成业务能力与数据兼容性。

## 4. 非目标

- 不改变 SQLite schema、密码哈希或会话模型。
- 不重写论文、证据、引用导入和导出算法。
- 不增加云同步、在线账户、协作或权限角色。
- 不开放 Chromium 开发者工具。
- 不为本轮新增移动端或触摸端专用布局。
- 不引入新的全局状态管理库。

## 5. 信息架构

```text
┌──────────────────────────────────────────────────────────────┐
│ 品牌 / 当前论文        全局搜索       检查  主题  账户  更多 │ 56px
├────────────────┬─────────────────────────────────────────────┤
│ 论文资料库      │                                             │
│ 搜索与筛选      │              论文编辑画布                   │
│                │                                             │
│ 论文列表        │  标题                                       │
│                │  作者 · 年份 · 来源 · 状态                   │
│                │  ─────────────────────────                  │
│                │  概览 / 笔记 / 证据                          │
│                │                                             │
└────────────────┴─────────────────────────────────────────────┘
                                      ┌────────────────────────┐
                                      │ 质量检查或账户抽屉     │
                                      │ 宽约 400px             │
                                      └────────────────────────┘
```

### 5.1 顶部栏

- 固定高度 56px。
- 左侧显示产品标识与当前论文的截断标题。
- 中部提供全局搜索入口；搜索范围为当前账户论文库。
- 右侧依次为质量检查、主题/显示设置、账户和更多操作。
- “检查”按钮显示当前论文待修问题数量。
- 删除所有开发者工具入口；`BrowserWindow.webPreferences.devTools` 继续保持 `false`。

### 5.2 论文资料库

- 默认宽度 264px，可折叠。
- 顶部保留搜索与状态/标签筛选。
- 论文行以标题、作者/年份、一个状态信息为主，减少标签堆叠。
- 当前论文使用整行选中背景和左侧强调条，不只依靠文字或弱边框。
- 折叠后保留一个明确的重新展开入口。

### 5.3 编辑画布

- 占据双栏结构中的全部剩余空间。
- 内容最大宽度约 900px，并随窗口宽度平滑收缩。
- 论文标题约 30px，最多三行；长标题不应吞噬全部首屏。
- 论文属性区改为紧凑且可识别的网格/行布局。
- 输入控件默认展示轻量表面或边界，用户无需悬停才能判断可编辑。
- “概览 / 笔记 / 证据”保留，但提升活动状态和内容层级。
- 正文基础字号不低于 14px；侧栏元信息不低于 12px。
- 中文标签不使用无意义的全大写转换和过度字距。

### 5.4 质量检查抽屉

- 由顶部“检查”按钮打开，默认不占用工作区宽度。
- 宽约 400px，从右侧覆盖打开，不挤压编辑画布。
- 包含质量问题、材料自查、工作台统计、导入导出。
- 待修项目支持定位到对应论文属性或编辑区。
- 与账户抽屉互斥，同一时间只打开一个主抽屉。

### 5.5 账户抽屉

- 未登录：登录/注册分段、对应表单和本机账户说明。
- 已登录：身份摘要、个人资料、修改密码、退出登录。
- 宽约 400px，替代当前约 280px 的狭长气泡。
- 关闭抽屉时保留当前未提交表单；成功提交或退出后再按业务清理。
- 不改变现有 `desktopApi.auth` 或数据库逻辑。

### 5.6 空状态

- 未登录和空账户都保留顶部栏与左侧资料库框架，避免界面突然切成孤立空白页。
- 未登录：编辑区域中央显示登录/注册引导。
- 已登录空库：显示“新建论文”和“导入资料库”两个主要入口。
- 会话恢复期间显示稳定的加载状态，避免短暂闪现未登录页面。

## 6. 三套主题系统

主题不仅替换主色，还分别定义应用背景、侧栏、编辑画布、输入表面、边框、阴影、选中态、浮层、状态标签和滚动条。

### 6.1 冰川蓝（默认）

- 应用背景：淡蓝灰。
- 侧栏：冷灰蓝，和编辑区形成稳定但克制的分区。
- 编辑画布：纯白或接近纯白。
- 强调色：清晰蓝色。
- 边框：明确但不过重；阴影轻且偏冷。
- 目标：现代、干净、专业，作为默认主题。

### 6.2 暖纸白

- 应用背景：暖灰米色。
- 侧栏：亚麻灰。
- 编辑画布：象牙白，表现独立纸张表面。
- 强调色：低饱和琥珀棕。
- 边框与阴影：偏暖、柔和，减少电子屏冷感。
- 目标：适合长时间阅读，和冰川蓝产生明显材质差异。

### 6.3 午夜黑

- 应用背景：深蓝黑。
- 侧栏：比编辑区更深。
- 编辑画布：深石墨。
- 强调色：冰蓝。
- 边框：在深色表面上有足够可见度；阴影弱化，主要靠明度分层。
- 目标：夜间友好、高对比、避免纯黑带来的刺眼反差。

### 6.4 显示设置

- 顶层设置优先展示主题选择。
- 字体、文字对比度和界面对比度归入“高级显示设置”。
- 主题、字体和对比度继续写入现有 localStorage key，兼容已有用户偏好。
- 界面字体与文档阅读字体应分开：导航和表单保持系统无衬线字体；文档内容可选阅读字体。

## 7. 组件边界

```text
App
├─ AppHeader
├─ PaperLibrary
├─ PaperWorkspace
│  ├─ PaperMetadata
│  ├─ ReadingNotes
│  └─ EvidenceEditor
├─ QualityDrawer
├─ AccountDrawer
├─ DisplaySettings
└─ EmptyWorkspace
```

### 7.1 职责

| 组件 | 职责 | 主要依赖 |
|---|---|---|
| `AppHeader` | 品牌、当前论文、搜索、抽屉与更多操作入口 | 当前论文、检查数量、UI callbacks |
| `PaperLibrary` | 搜索、筛选、列表、选中与折叠 | papers、selectedId、filters |
| `PaperWorkspace` | 组织论文属性、笔记与证据编辑 | selected paper、update callbacks |
| `PaperMetadata` | 标题和基础引用属性 | Paper、update callback |
| `ReadingNotes` | 概览与笔记字段 | Paper、update callback |
| `EvidenceEditor` | 证据新增、编辑与删除 | evidence、callbacks |
| `QualityDrawer` | 质量问题、自查、统计、导入导出 | selected、papers、import/export callbacks |
| `AccountDrawer` | 登录、注册、资料、改密、退出 | auth state 与 auth callbacks |
| `DisplaySettings` | 主题与高级显示偏好 | theme/font/contrast state |
| `EmptyWorkspace` | 未登录、加载与空库引导 | session status、callbacks |

组件仅接收所需状态和 callback；数据库与 IPC 仍由现有应用层逻辑负责，不在展示组件中直接访问。

## 8. 状态与数据流

### 8.1 抽屉状态

- 使用单一状态：`activeDrawer: 'quality' | 'account' | null`。
- 打开一个抽屉会关闭另一个。
- 资料库折叠状态独立持久化或保持在当前会话；第一期只需当前会话状态。

### 8.2 保存状态

自动保存增加可见状态：

```text
idle → saving → saved
              ↘ failed → retry → saving
```

- 编辑后立即更新本地 React 状态。
- 桌面端调用现有 `desktopApi.library.save`。
- 顶部显示“保存中”“已保存”或“保存失败”。
- 保存失败状态持续存在，不只显示瞬时 toast；提供重试入口。
- 不改变 Web 开发模式的 localStorage fallback。

### 8.3 会话启动

- 增加明确的 `sessionStatus: 'loading' | 'authenticated' | 'anonymous'`。
- 加载期间显示骨架或稳定加载面板。
- 会话恢复完成后再决定未登录或论文工作区，避免闪烁。

## 9. 响应式与窗口约束

- 目标窗口范围：Electron 最小 1100×720 至常见 1920×1080。
- 1100px 时：资料库保持可用，编辑区不得被固定质量栏占用；质量和账户使用覆盖抽屉。
- 资料库折叠后，编辑区应获得释放的宽度。
- 移除当前 1180px 隐藏右栏造成的布局跳变，因为右栏改为抽屉。
- 不依赖 820px 以下断点作为主要桌面行为；低于产品最小宽度不作为本期验收目标。
- 顶栏操作不足时优先收进“更多”，而不是增加顶栏高度或换成多行。

## 10. 错误处理

| 场景 | 界面行为 |
|---|---|
| 论文自动保存失败 | 顶部持续显示失败状态与重试按钮，保留当前编辑内容 |
| 会话恢复失败 | 显示明确错误并允许重新登录，不展示旧账户论文 |
| 账户表单失败 | 抽屉内显示错误，保留非敏感输入；密码按现有策略清理 |
| 旧数据迁移失败 | 不标记迁移完成，不删除 localStorage，允许下次重试 |
| 导入文件无效 | 保持现有错误信息，不覆盖当前账户论文库 |
| 主题设置损坏 | 回退冰川蓝默认主题，不阻塞应用启动 |

## 11. 测试与验收

### 11.1 自动化

- 现有账户、SQLite、论文隔离和导入解析测试全部继续通过。
- 为主题映射增加测试：三个主题必须生成不同的核心表面 token。
- 为抽屉互斥状态增加测试。
- 为 session loading / anonymous / authenticated 三个空状态增加测试。
- 为保存状态机增加成功、失败和重试测试。
- TypeScript 构建与 Vite 生产构建通过。

### 11.2 视觉验收

1. 三套主题在同一论文页面截图中能被立即区分，不依赖读取主题名称。
2. 1100×720 窗口无横向溢出、栏位重叠或文字不可用。
3. 1360×860 下编辑区明显大于旧三栏布局。
4. 论文标题、正文、侧栏信息有连续且清晰的字号层级。
5. 默认状态下可判断输入区域可编辑。
6. 左栏选中论文无需仅靠颜色文字即可识别。
7. 质量抽屉和账户抽屉互斥且可正常关闭。
8. 登录前、会话加载中和空账户不出现孤立白屏或错误工作区闪烁。
9. F12、Ctrl+Shift+I 和菜单均不能打开开发者工具。

### 11.3 业务回归

- 注册、用户名/邮箱登录、退出、资料保存、改密和会话恢复。
- 用户 A/B 论文库互不可见。
- 新建、编辑、删除、恢复示例和自动保存。
- 资料库导入导出、引用导入和 Markdown 导出。
- 旧 localStorage 论文确认迁移。

## 12. 实施顺序

1. 提取主题 token 与基础布局变量。
2. 引入抽屉/折叠/会话加载/保存状态模型。
3. 拆分顶部栏、论文库和工作区组件。
4. 将质量检查迁入 `QualityDrawer`。
5. 将账户功能迁入 `AccountDrawer`。
6. 统一空状态与会话加载状态。
7. 完成三套主题的独立表面设计。
8. 完成窗口、视觉和业务回归。

## 13. 完成定义

只有在以下条件全部满足后，本轮重设计才算完成：

- 双栏 + 抽屉结构在项目本体运行；
- 三套主题视觉明显不同；
- 账户与质量检查不再使用旧狭长气泡/固定右栏；
- 1100×720 最小窗口可用；
- 自动保存有持续状态与失败重试；
- 所有账户、数据库和论文业务回归通过；
- 开发者工具保持禁用；
- 生产构建通过。
