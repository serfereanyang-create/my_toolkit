# 原创像素体素沙盒游戏设计

**日期：** 2026-07-18  
**状态：** 已定稿（用户已授权后续设计决策由开发者自行完成）

## 1. 项目目标

在 `C:\Users\34516\ZCodeProject\voxel-game` 中创建一个独立的桌面浏览器游戏。它采用经典像素方块沙盒的操作语言，但所有名称、界面、程序纹理和代码均为原创，不复制《我的世界》的贴图、声音、角色、标识或源代码。

首版交付一个可完整游玩的单人创造模式原型：玩家能进入程序生成的三维方块世界，以第一人称探索、飞行、破坏和放置方块，并在刷新页面后恢复世界改动与角色位置。

## 2. 成功标准

首版必须满足以下条件：

1. 运行 `npm install` 和 `npm run dev` 后，可在桌面版 Chrome、Edge 或 Firefox 中进入游戏。
2. 首次打开显示加载界面和操作说明，点击后进入鼠标锁定的第一人称游戏。
3. 玩家可以行走、冲刺、跳跃、开启或关闭飞行，并与固体方块正确碰撞。
4. 玩家可以瞄准六格内的方块，左键破坏、右键在相邻空位放置方块，且不能把方块放进玩家身体。
5. 屏幕包含准星、九格快捷栏、选中方块名称、性能信息和暂停菜单。
6. 世界按固定种子确定性生成，并包含三个可切换维度：多群系地表、熔岩洞窟、浮空群岛。
7. 世界使用区块流式加载；区块边界不可出现明显裂缝或重复表面。
8. 浏览器本地保存种子、玩家状态、设置和被修改的方块；刷新后能恢复。
9. 使用原创程序化像素纹理；项目不包含或下载《我的世界》的版权资产。
10. 在常见 1080p 桌面环境中以四区块视距运行时，目标为 60 FPS，验收底线为稳定 45 FPS；首次可操作时间目标小于五秒。
11. 核心算法有自动化测试，生产构建成功，并完成一次真实浏览器游玩检查。

## 3. 首版范围

### 包含

- 单人离线创造模式
- 第一人称鼠标和键盘操作
- 行走、冲刺、跳跃、重力、碰撞、飞行
- 方块选择、破坏和放置
- 九格快捷栏与方块选择面板

- 浏览器 IndexedDB 增量存档
- 音量、灵敏度、视距和画质设置
- 原创程序化像素纹理与简短程序音效
- 桌面浏览器响应式 HUD

### 不包含

- 生存生命值、饥饿值、掉落物和物品耐久

- 红石式电路、液体模拟和复杂光照传播
- 无限垂直高度
- 与其他游戏完全一致的地形、材质、音效或界面

这些内容可作为后续版本扩展，但不会阻塞首版交付。

## 4. 技术方案选择

### 采用：TypeScript、Vite 和 Three.js 自研体素层

- Three.js 负责 WebGL 渲染、相机、材质和场景管理。
- TypeScript 实现体素数据、区块生命周期、程序生成、网格、物理、交互和存档。
- HUD 使用原生 HTML/CSS，避免为少量界面引入完整 UI 框架。
- Vitest 运行算法单元测试；Playwright 运行关键浏览器冒烟测试。

这与现有工作区的 TypeScript/Vite/Three.js 能力最接近，又能让新游戏作为完全独立项目存在。

### 未采用的方案

- **Babylon.js：** 内置碰撞与资源系统更丰富，但会增加新框架学习和工程约束，体素网格仍需自研。
- **Godot Web 导出：** 编辑器工作流成熟，但当前环境没有 Godot 项目基础，Web 导出、自动测试和资源管理会引入另一套工具链。

## 5. 世界与维度设计

世界由 `WorldId + seed + chunk coordinates` 唯一决定。水平区块尺寸为 `16 × 16` 方块，垂直范围固定为 96 方块。运行时仅保留玩家视距内的区块，并优先生成玩家朝向和附近区块。

### 5.1 青原界（多群系地表）

- 分形噪声形成平原、丘陵和高地。
- 温度与湿度噪声决定草原、森林、沙地和雪原。
- 表层包括草、土、沙、雪；下层为岩石。
- 低洼处形成固定海平面的水域。
- 以确定性规则放置树木、灌木和少量发光晶体。
- 天空随时间缓慢变化，夜晚保持足够亮度以便创造模式建造。

### 5.2 赤核界（熔岩洞窟）

- 大部分空间由赤岩构成，三维噪声挖出连通洞穴。
- 底层分布熔岩湖；首版熔岩不流动，接触仅产生视觉提示，不造成伤害。
- 发光晶体和灰烬柱提供地标与色彩层次。
- 使用暗红雾、低环境光和暖色点缀表现地下空间。

### 5.3 云屿界（浮空群岛）

- 三维密度场形成大小不同的浮岛和天然拱桥。
- 岛屿上表面覆盖苔草，内部为云石，底部形成锥状岩层。
- 较大岛屿生成风木和发光花簇。
- 玩家落出世界下界时返回当前维度出生点，不损失任何内容。

### 5.4 维度切换

暂停菜单包含维度选择器。切换时保存当前维度位置，显示短暂加载遮罩，然后传送到目标维度已保存的位置或安全出生点。首版不实现实体传送门，以避免把资源投入一次性机制。

## 6. 方块与视觉语言

首版方块集合包括：草土、泥土、岩石、砂、雪、原木、树叶、木板、玻璃、水、赤岩、灰岩、熔岩、云石、苔草和发光晶体。

纹理由运行时 Canvas 纹理生成器创建 16×16 像素图块，再组合为纹理图集：

- 每种方块使用有限色板、颗粒噪点和少量边缘变化。
- 草方块的顶部、侧面和底部可使用不同图块。
- 使用最近邻采样，不做像素平滑。
- 颜色和图案保持原创；不临摹其他游戏纹理。
- 水和玻璃使用独立透明材质；熔岩和晶体使用独立发光材质。

天空采用颜色渐变、方向光、环境光和距离雾。方块被瞄准时显示细线框。破坏与放置播放由 Web Audio API 合成的短音效，不引入外部音频资产。

## 7. 玩家控制与交互

### 默认控制

- `W/A/S/D`：移动
- 鼠标：观察
- `Space`：跳跃；飞行时上升
- `Shift`：冲刺；飞行时下降
- `F`：开启或关闭飞行
- `1–9` 或滚轮：选择快捷栏方块
- 左键：破坏目标方块
- 右键：放置选中方块
- `E`：打开方块选择面板
- `Esc`：释放鼠标并打开暂停菜单
- `F3`：显示或隐藏调试信息

### 物理

玩家使用轴对齐包围盒，固定时间步长更新：

- 地面模式应用重力、地面加速度、空中控制和跳跃速度。
- 冲刺提高水平速度。
- 飞行模式忽略重力，支持六方向移动，但仍默认参与方块碰撞。
- 碰撞按 X、Y、Z 轴分离求解，避免高速穿墙和卡入方块。
- 出生点通过从候选位置向下寻找固体表面、向上确认两格空间来选取。

### 方块交互

使用体素 DDA 射线遍历而不是对每个方块创建独立网格对象：

- 最大触达距离为六格。
- 射线命中返回方块坐标、进入面的法向和前一个空格坐标。
- 破坏操作将命中位置改为空气。
- 放置操作写入前一个空格，并先检查与玩家包围盒是否相交。
- 修改边界方块时，同时标记相邻区块网格为脏状态。

## 8. 区块、网格与性能

### 数据表示

- 每个区块使用紧凑的 `Uint8Array` 存放方块 ID。
- `ChunkStore` 管理区块状态：缺失、排队、生成中、待构网格、就绪、卸载。
- 程序生成结果不全部持久化；存档只记录相对种子地形的方块增量。

### 网格构建

- 不为每个方块创建独立 Three.js `Mesh`。
- 仅生成与空气或透明方块相邻的可见面。
- 对不透明方块使用贪心网格合并共面、同材质表面。
- 透明方块按独立几何和渲染顺序处理。
- 区块网格包含位置、法线、UV 和基础环境遮蔽信息。
- 区块生成和网格计算放入 Web Worker，主线程只提交任务和上传几何。

### 调度与资源上限

- 默认视距为四个区块，可在 2–8 间调整。
- 每帧限制几何上传数量，避免移动时长帧卡顿。
- 超出卸载半径的区块释放几何与材质引用，但保留未刷盘的修改。
- 维度切换取消旧维度尚未开始的任务，并通过任务版本号丢弃迟到结果。

主要边界：

- `GameApp` 只负责装配子系统和状态切换。
- `World` 提供方块查询与修改接口，不向调用者暴露区块数组布局。
- 维度生成器只根据种子和坐标返回方块数据，不依赖渲染器或存档。
- 网格器只读取带边界采样能力的体素视图并返回可传输几何数据。
- `PlayerController` 将输入意图交给纯物理层，渲染相机只消费最终位置和朝向。
- `SaveRepository` 封装 IndexedDB；世界逻辑不直接调用浏览器存储 API。
- UI 通过事件和只读游戏状态快照通信，不直接修改区块内部状态。

## 10. 数据流

1. 启动时读取设置、存档元数据和三个维度的玩家位置。
2. `World` 根据当前位置计算所需区块并向 Worker 调度生成任务。
3. Worker 生成体素，叠加该区块的存档增量，再生成网格数据。
4. 主线程接收带世界版本和区块坐标的结果；过期结果被丢弃。
5. 渲染器上传几何并将区块加入场景。
6. 每个固定物理步读取输入，查询 `World` 完成碰撞和射线交互。
7. 方块修改立即写入内存增量表、更新相关区块网格，并通过防抖队列写入 IndexedDB。
8. 暂停、失焦、维度切换和页面隐藏时强制刷新待保存数据。

## 11. 存档设计

IndexedDB 数据库包含：

- `worldMeta`：存档版本、世界种子、创建时间、最近游玩时间。
- `playerState`：每个维度的位置、朝向、飞行状态、快捷栏选择。
- `chunkEdits`：键为 `worldId:chunkX:chunkZ`，值为局部坐标和方块 ID 的稀疏增量。
- `settings`：灵敏度、视距、音量、画质和调试开关。

每次保存带 schema 版本。未来结构变化通过显式迁移函数处理。若单个区块数据损坏，只忽略该区块增量并显示非阻塞警告，不影响其他区块。菜单提供“新建世界”和“重置当前世界”，重置操作必须二次确认。

## 12. 界面状态

游戏有以下顶层状态：

- `booting`：初始化 WebGL、纹理、Worker 和存档。
- `ready`：显示标题、世界信息和“进入世界”按钮。
- `loading-world`：生成出生区块并显示进度。
- `playing`：鼠标锁定，更新物理和世界。
- `paused`：释放鼠标，暂停玩家输入，但保留渲染。
- `error`：显示可执行的恢复建议。

加载界面展示真实的已完成/所需出生区块数量，而非虚假计时器。暂停菜单提供继续、维度切换、设置、保存并返回标题。

## 13. 错误处理与降级

- 不支持 WebGL2 时显示兼容性说明，不进入空白画布。
- Worker 初始化失败时可降级为主线程分帧生成，并降低默认视距。
- IndexedDB 不可用时进入临时会话模式，在 HUD 中持续提示“本次改动不会保存”。
- 纹理生成失败时使用带方块 ID 颜色的后备纹理。
- 捕获不可恢复的主循环异常，停止更新并显示重新载入按钮，避免无限报错。
- 页面失焦会清空按键状态，防止返回游戏后角色持续移动。

## 14. 测试策略

### 单元测试

- 相同种子与坐标生成完全相同的区块。
- 三个维度的出生点搜索均返回安全位置。
- 区块坐标、负数世界坐标和局部坐标转换正确。
- 跨区块方块读写和边界脏标记正确。
- 贪心网格对实心立方体只产生六个四边形，并正确剔除相邻面。
- 透明和不透明方块不会被错误合并。
- AABB 在地面、墙角、天花板和区块边界的碰撞正确。
- DDA 射线返回正确命中格、面法线和放置格。
- 存档增量序列化、反序列化和 schema 迁移可往返。

### 浏览器测试

- 页面无控制台错误并显示“进入世界”。
- 点击进入后创建 WebGL 画布、HUD 和九格快捷栏。
- 可通过测试接口加载固定小世界，验证破坏、放置和刷新恢复。
- 暂停菜单能切换维度并返回可游玩状态。
- WebGL 不可用模拟场景显示明确错误信息。

### 人工验收

- 在真实浏览器连续游玩至少十分钟。
- 步行和飞行跨越多个区块，观察加载卡顿、边界裂缝与内存增长。
- 在区块边界放置和破坏方块，再刷新验证恢复。
- 依次进入三个维度，确认地形、雾、光照和出生安全。
- 检查快捷栏、暂停、设置、鼠标锁定和窗口尺寸变化。
