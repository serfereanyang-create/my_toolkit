# YOYcode 界面改造进度

目标：持续小步改造，使 YOYcode 的视觉、交互与日常工作体验达到可与 Codex 比较的完成度。目标仍在进行中，不以单次构建通过或局部样式更新代替整体完成。

## 验收范围

- 主界面、会话列表、顶栏、空状态和输入区使用一致的字号、间距、颜色和焦点反馈。
- 浅色和深色都能清晰阅读；缩窄窗口、打开侧栏和放大字号后，关键操作不被截断。
- 输入、引用、模型选择、审批、运行、停止和错误反馈保持真实可用。
- 代码块、工具步骤、文件改动和审查结果能让用户快速理解发生了什么。
- 文件、编辑器、预览、设置等主要工作流继续按同样标准改进并验证。
- 每轮保存真实组件渲染证据，执行与改动匹配的检查，记录失败而不盲目重复测试。

## 2026-10-21：确认弹窗与保存冲突的交互审计

本轮先对真实 React 组件执行 Electron/CDP 键盘操作，复现了 7 项弹窗缺陷：焦点在取消或拒绝时 Enter 仍执行确认、父组件更新抢走焦点、主区的尺寸隔离限制固定弹层、审批快捷键被多处重复处理、Ctrl+A 触发审批，以及 Guard 提交期间 Escape 重复提交。随后补测又复现了 4 项保存异步缺陷及 2 项叠层焦点缺陷；每项均保留具体断言，修复后再验证。

### 发现与修复

1. **旧窗口导致等待与进程回收**：启动页关闭后继续使用旧编号，旧实现会等待窗口；在临时缩短到 600 ms 的 RPC 截止期限下，基线实际复现超时并回收整个应用，证据保存在 `out/background-app-windows/baseline.json`。现在旧编号立即返回明确错误，新增 `background_app_windows` 刷新列表。多窗口写入必须明确指定 `windowId`，不会默认落到第一个窗口；切换窗口会清除旧图。真实点击关闭窗口时，还修复了旧渲染帧 Promise 不结束的问题，让等待随目标渲染器关闭而结束，其他窗口保持运行。
2. **参数类型推断错误**：已实测旧实现把 `{ "appId": "app-id", "x": 120, "y": 80 }` 的 `appId` 宣告为 number，源于类型推断读取了相邻字段的数字。现在按字段自己的值推断，并让工具优先提供明确 JSON Schema。后台工具保留 ID、整数窗口编号、坐标互斥关系与必填项；MCP 不再从截断到 240 字符的提示重建参数，而是保留原始嵌套 schema。OpenAI Chat、Responses、Anthropic 与 Gemini 均验证了参数传递。按官方 OpenAI Docs 核对 Responses 的默认严格化行为后，明确使用非严格模式保留工具的可选字段，运行时参数与审批仍独立严格校验。
3. **Gemini 漏图**：原消息转换只读取文字，丢掉用户附件和工具截图。现在请求体保留 `inlineData` 图片与工具结果上下文，显式结构参数使用 `parametersJsonSchema`。验证覆盖本地构造的真实请求体，不等同付费端点的在线识图验收。
4. **流式结束后遗留 90 秒计时器**：此前专项 38 项断言虽然完成，Node 仍运行约 90 秒。定位到 SSE 每次读取都创建 idle timer，但读取成功、EOF 或失败后均未清除。现在统一在该次读取结束时清理；超时或消费者提前退出时取消 reader。新增独立 Node 子进程验证自然退出，以及空闲超时后底层流取消、锁释放；没有模拟时钟。新专项 12/12、约 215 ms，通过；最终完整 Node 套件 1047/1047，通过。
5. **DOM 快照带出敏感输入值**：共享检查脚本曾把无 aria-label 的 password / hidden 输入值放进元素名称。现在这两种控件的值会脱敏，仍保留类型和选择器；真实 Electron 夹具验证密码与隐藏令牌样例不出现在响应数据中。没有读取真实用户凭据。

## 2026-10-23：可取消执行、持久队列与跨窗口恢复

本轮把“停止”从按钮状态扩展成完整执行语义。桌面端先发送协作取消，CLI 通过 `AbortSignal` 贯穿模型请求、四种 provider 流式读取、重试退避、上下文压缩、自动审核、前台命令和后台命令 Job；后台网页与隐藏 Electron 应用也接收同一取消信号。取消后继续保留当前会话和 CLI 子进程，只有进程不响应时才按所属子进程树兜底结束。错误终止不会伪造成功的 `turn_done`，终止失败也不会启动替代子进程。

模型请求总时限增加到 CLI 配置和设置页面，默认 5 分钟，支持 5 / 15 / 30 / 60 分钟。设置修改会触发后续桥接使用新参数，但不会泄露或迁移密钥。流式响应收到 `[DONE]` 会立即关闭连接，主动取消和总时限都不会触发 transport fallback 重发。Gemini 的增量文字也会正常进入 UI。

## 2026-10-23：质量分析面板的评分可读性、空状态与图标语言

本轮处理“接下来的工作”第 2 项：质量分析的评分、复杂度、代码异味和依赖结果的阅读密度、空状态与过期状态。

先看上一轮留下的真实渲染 `out/workspace-review/quality.png`，记录到 8 个问题：

4. 指标卡是 `<div onClick>`：不能聚焦、键盘无法进入；副文本是蓝色，看起来像链接却不可点。

6. 结果回来之前是一个空壳：没有加载态，`🚨 需要立即关注` 下面是空列表。
7. 边界数据会算出坏值：`totalFunctions = 0` 时分布条宽度为 `NaN%`；`byType` 为空时 `Math.max()` 为 `-Infinity`；异味严重程度、异味类型和热点风险都是裸英文 id。
8. 标签页没有 `tablist / tab` 语义，也没有方向键。

改法：

- 评分改为按出现率计算（每 100 个函数、每 100 个模块），三项扣分在抬头平铺成明细（复杂度 / 代码异味 / 依赖健康），明细之和与总分对应。同一夹具从“0 分 F”变为 75 分 B“良好”；代码规模翻倍不会无故降分。没有可分析函数时不给分数，而不是给 100 分 A。
- 抬头圆环 120px → 64px、内边距 32px → 16/20px、指标数值 32px → 28px，首屏能看到“需要立即关注”。
- emoji 全部换成 lucide 图标（`AlertTriangle` / `CheckCircle2` / `RefreshCw` / `Loader2` / `ChevronRight` / `X`）；风险分布图例改用 `--danger/--warn/--ok` 的圆点，“高/主要”单独取 `color-mix(--danger 55%, --warn)`，四个级别对应四种颜色，不再和“严重”合成一段。
- 指标卡改成真正的 `<button>`，带 `aria-label`、`:focus-visible` 焦点环与右侧箭标；异味条目同样从可点击 `div` 改成按钮，可按回车打开文件。
- 分析范围增加可见标签、`aria-label`、回车即分析、分析中禁用；刷新按钮改为图标 + “重新分析”，并带 `aria-busy`。
- 补加载态（`aria-busy` + 正在分析…）、无结果态，以及每个标签页自己的空状态（没有可分析函数 / 没有检测到异味 / 依赖关系干净），空数据不再出现 `NaN`、`Infinity`、`undefined` 文案或宽度。
- 风险等级、异味严重程度、异味类型统一中文标签（严重/主要/次要/提示、超长函数/深层嵌套…），原始 id 保留在 `title` 上便于核对。
- 标签页补 `role=tablist / tab / tabpanel`、`aria-selected`、方向键与 Home/End 切换。

实现文件：`src/components/QualityDashboard.tsx`、`src/workspace-shell.css`（指标卡悬停色与面板统一）、`scripts/workspace-preview.tsx`（质量调用的场景开关与调用记录）、`scripts/workspace-smoke.cjs`（质量面板检查从 1 项扩到 5 项，含深浅色与空范围截图）、新增 `src/components/QualityDashboard.test.tsx`。

## 2026-10-23：对话输出的流式体感——从「整块砸出来」到每 31ms 一格

用户反馈「输出一点都不动态」。先量清楚是哪一段坏了，再改。

### 先证明上游没坏

用本地 SSE 桩（60 个 token，25ms 间隔）驱动真实 CLI `--desktop-bridge`，统计 stdout 事件时间戳：61 个 `assistant_delta`，中位间隔 **31ms**，每次 12 字。CLI → bridge → 主进程这一段是逐块转发的，`main.cjs` 也是来一个转发一个。所以瓶颈在渲染，不在链路。

### 渲染层的实测（改前）

新建测量台：`scripts/conversation-preview.tsx` 挂真实 `ConversationStream` + 真实 `appReducer`，`scripts/conversation-stream-smoke.cjs` 按实测节奏（31ms/个）推 60 个 delta，用 `flushSync` 量每次 delta 的同步渲染开销。离屏窗口不保证按 60Hz 出帧，量同步渲染成本才可复现、可比。

| 场景 | 每次 delta 渲染中位 | P95 | 60 个 delta 合计 | 长任务 |
| --- | --- | --- | --- | --- |
| 24 轮历史（75 行 / 4904 节点） | 54ms | 70.3ms | 3323ms | 46 个 / 2640ms |
| 60 轮历史（183 行 / 12212 节点） | 125.3ms | 158.6ms | 7630ms | 60 个 / 7610ms |

根因只有一个：**每个 delta 都把整个会话列表重渲染一遍**。上游 1.9 秒就吐完，渲染要 7.6 秒，所以看到的是「卡住 → 猛吐一大段」。

### 改法

1. **行级 memo**：`MemoRow` / `MemoTurnRow`。reducer 追加 delta 时只替换流式那一行，其余 item 引用不变，memo 直接跳过 —— 这是 54ms → 1.9ms 的全部来源。
2. **回调引用稳定**：父组件传的是内联箭头函数，每帧都是新引用，会击穿 memo。用 ref 转发成稳定函数（`stableApprove` / `stableEditUser` / `stableUndo` / `stableOpenFile`）。
3. **`now` 只给还在跑的 turn**：已结束的行传 0。此前每秒的计时 tick 会把全部历史 turn 行刷一遍。
4. **大纲延迟**：新增 `AssistantText`，用 `useDeferredValue` 把 `MessageOutline`（对同一段文字再走一遍找标题）降到低优先级；正文按原速更新，光标和滚动跟手。
5. **指示条给动态读数**：`生成中 N 字 · X 字/秒`，悬停显示首字到达延迟（TTFT）。数字用 `font-variant-numeric: tabular-nums`，跳字时不抖。

### 改后

| 场景 | 稳态中位 | 稳态 P95 | 稳态最大 | 稳态合计 | 长任务 |
| --- | --- | --- | --- | --- | --- |
| 24 轮历史 | 1.9ms | 2.7–3.4ms | 11.2ms | 147 → 106ms | 0 |
| 60 轮历史 | 2.5ms | 3.6–4.5ms | 18.5ms | 231 → 166ms | 0 |

流式气泡**首次挂载**是一次性开销（10–21ms），单独报告、不进稳态预算 —— 否则门禁量的只是挂载那一下。
